01 · Getting Started & Setup

First-Time Setup Guide
  1. Wait for the footer to report that SteamCMD is ready.
  2. Select Add Server, enter a unique name, and choose a game definition.
  3. Complete only the template-supported world, network, automation, Discord, and launch fields.
  4. Choose the default folder or a custom empty folder, then save.
  5. Select the server and press Start. Follow Activity & Diagnostics while Synix installs and launches it.

Save remains locked until the exact requirement shown at the bottom of Server Setup is fixed.

Server Setup Page Guide

General holds identity and game choices. World Generation holds template-supported world values. Network & RCON handles service ports. Automation controls backup, update, restart, and Discord options. Install & Launch sets the folder and optional extra arguments.

Disabled controls are intentionally unsupported by the selected definition.

After Saving: Install, Start, and Verify

Select the new row and press Start. Synix installs missing files, displays validation and launch progress, binds the real process, and runs the supported startup probe. Some games create their config only after the first complete boot, so stop cleanly before editing generated files.

Understanding Server {Identity}

Every server uses a unique, sanitized identity to keep multiple instances from sharing config and save paths. Windows-invalid characters and spaces are removed from the identity used in folders and arguments.

File Structure, Default Directories & Custom Paths
  • C:\Synix: Synix data and shared resources
  • C:\Synix\SteamCMD: shared SteamCMD files
  • C:\Synix\Games\[Game]\[Server]: default server location
  • C:\Synix\BackupGames\[Game]\[Server]: default backup repository

A server can use a custom path selected during setup.

WinGet Package Installation

Install with winget install --exact --id ubidzz.Synix. Use winget upgrade --exact --id ubidzz.Synix to update or winget uninstall --exact --id ubidzz.Synix to remove the installed application.

02 · Dashboard & Controls

Main Dashboard Operations

Select a server row to unlock its action bar. Start performs pre-flight and optional automation work. Restart completes a verified stop before relaunching. Stop waits for the tracked process to exit and uses a process-tree shutdown only if the game will not stop cleanly. Activity & Diagnostics is the first place to check when a status looks wrong.

Server Options Menu

Depending on the game, Server Options can open folders, edit config, update, validate files, export a batch file, back up, restore, run connection tests, and delete the server. Unsupported actions are hidden intentionally.

Server Details & Double-Click Inspector

Double-click a server row to open Server Info. It shows identity, ports, saved settings, automation, paths, arguments, process state, CPU, and RAM. Closing Server Info stops its own monitoring timer, not the game server.

Live Resource Telemetry Graph

The dashboard cards summarize active managed game-server usage. Resource Monitor lists each bound process with server name, PID, executable, CPU, and RAM. Closing the monitor does not stop servers.

Global Settings Menu & Privacy Mode

Settings covers console behavior, theme, SteamCMD speed, backups, transfer packages, privacy, problem reporting, approved elevated tasks, health checks, and development-only tools. Privacy Mode hides IP addresses, passwords, and other sensitive values while screen sharing.

Dark Mode, Light Mode, and Console Windows

Theme changes do not restart servers. Hiding the native server console works for supported launchers; games requiring an interactive manager, such as Space Engineers, keep the required window visible.

03 · Server Configuration

Adding and Editing Servers

Add Server starts a new definition. Configure loads an existing server. Stop the server before changing ports, paths, versions, or launch arguments. The bottom validation message names the missing or conflicting value that must be fixed before Save unlocks.

The Port Trio & App Port Architecture

The Game Port carries gameplay traffic. Query Port is used by supported browsers or status protocols. RCON Port is for remote administration. App Port is an extra API or companion endpoint used by certain games. Every enabled port must be unique among active services and other Synix servers.

Using the Format-Aware Config Editor
  1. Stop the server.
  2. Open Server Options → Open Config Editor.
  3. Use Structured View, search, and type filters to change supported values.
  4. Use Raw Preview to inspect the original.
  5. Save, then restart.

For supported INI, XML, JSON, and space-delimited files, Synix changes only the selected value spans so comments, spacing, quotes, and key order stay intact.

Config Editor Safety and Recovery

Back up before large edits, do not edit the same file externally while the editor is open, and keep each value’s expected type. The editor protects formatting but cannot guarantee that every value is valid for every game version.

04 · Networking & IP Rules

Local Link vs WAN Link Diagnostic

Test LAN first to confirm the server is reachable inside your network. WAN tests public reachability and can expose router, firewall, or protocol problems. The definition selects a supported A2S, TCP, HTTP, or other probe. Hidden tests mean the game has no dependable supported probe.

Port Forwarding Master Guide

Forward only the ports required by the game to the server PC’s stable LAN address, using the correct TCP or UDP protocol. Create matching Windows Firewall rules only when needed. Never expose RCON without a strong unique password.

NAT Hairpinning & Joining Your Own Server

Some routers cannot send a local client out through the public IP and back into the same network. If public joining fails from home but works for outside players, use the LAN address internally or check whether the router supports NAT loopback/hairpinning.

Steam Master Server Query Rules

A game may use separate gameplay and query ports, and the query protocol is often UDP A2S. A running process alone does not guarantee public listing; verify the correct query port, forwarding protocol, firewall rule, and game-specific public visibility setting.

Synix Network Guard

Network Guard uses approved elevated operations to inspect or clean Synix-related firewall rules. It is not a router configuration tool and does not replace ISP or hosting-provider DDoS protection.

05 · Maintenance & Discord

Smart Backup on Start

When enabled, Synix creates a protected archive before launch and applies the per-server retention limit. Stop the server before a manual backup when possible so rapidly changing world files are captured consistently.

Manual Backups and Restore Workflow

Backup Server creates an archive in the configured repository. Restore Server Backup appears only when archives exist. The server must remain stopped; restore stages the chosen archive and automatically rolls back if replacement fails.

Smart Update on Start & Manifest Validation

Update on Start asks the supported installer to update or validate before launch. SteamCMD uses its own manifest and validation process; Synix tracks the result and does not mark the server running until launch verification succeeds.

Discord Webhook Integration

Use one master webhook and choose its events, or add named destinations for different channels. Events include server status, restart, crash, install, update, validation, backup, restore, maintenance, and problems. Webhook URLs are protected locally and masked in the interface.

06 · Watchdog & Safeguards

Autonomous Watchdog Loop

The watchdog compares saved state with the tracked server process, updates runtime information, and detects unexpected exits. It does not blindly restart every process; configured automation and current operation state determine the next action.

Resource Guard (RAM Buffer & CPU Throttling)

Resource checks help Synix avoid starting work when the computer does not have a safe memory buffer. SteamCMD download limiting controls bandwidth, while server CPU and RAM remain visible for troubleshooting.

Process Rebinding on Application Restart

If Synix closes while a server keeps running, the next launch can inspect saved process information and safely rebind to a matching server process instead of starting a duplicate. Unmatched leftover processes are reported by the troubleshooter.

07 · Troubleshooting & System

No-Admin Philosophy & Windows Firewall

Routine Synix use is designed for a normal Windows account. Installing a game server does not automatically mean a firewall rule can be created without elevation. Enable Elevated System Tasks only when you want an approved Windows-level operation to request permission.

Missing Visual C++ Redistributables & DLL Errors

If a server reports a missing runtime DLL or closes immediately, run the System Server Troubleshooter and install the official Microsoft Visual C++ redistributable required by that game. Do not download random DLL files from third-party sites.

Windows SmartScreen & SAC Warnings

Unsigned independent releases can trigger Windows reputation warnings. Download only from the official Synix GitHub release. Review the publisher and file source before choosing More info → Run anyway. Smart App Control can block unsigned apps more strictly.

Where are My Server Backups Located?

The default location is C:\Synix\BackupGames\[Game]\[Server]. If a custom backup location is enabled, new archives go there. Changing the location does not move or delete older backups.

Reading Activity, Logs, and Crash Reports

Start with Activity & Diagnostics for the resolved launch, installer result, PID binding, probe, and shutdown sequence. Then check the game-specific log paths recorded in its definition. Use Report a Problem to create a privacy-filtered report without posting passwords or public IP addresses.

Server Stuck on Starting, Stopping, or Offline

Starting waits for the configured process or network proof. Stopping waits for the process tree to exit. If a state does not clear, use the troubleshooter to check missing files, port conflicts, leftover processes, and recent logs before forcing another start.

Why Connection Test Actions May Be Hidden

Synix shows LAN or WAN tests only when the game definition has a dependable supported probe. For other games, verify from the game client, official browser, native manager, or logs.

08 · Game Engines & Custom Rules

Internal IReadOnlyList<GameInfo> Database

Synix game definitions are built-in data, not downloaded plugins. They describe AppID, executable, argument tags, ports, config behavior, templates, warnings, runtimes, probes, and allowlisted post-install actions. The developer Definition Builder and Validator help keep additions consistent.

Dune: Awakening Setup & Definition Rules

Dune has special host requirements and is not treated like a normal headless SteamCMD server. Synix displays the definition’s hardware/Windows warning and keeps the special fields declarative so the rules remain visible in one game definition.

Rust & Rust+ Mobile App Integration

Synix supports Rust ports, identity, world values, passwords, RCON, and the Rust+ app port through the built-in definition. If Oxide is selected, Synix installs the official Oxide runtime only; users manage their own plugins in the server’s Oxide folder.

Minecraft Vanilla, Fabric, and Forge

Synix can prepare the selected Java runtime and supported Vanilla, Fabric, or Forge server files. Mods remain user-managed. Extra Java or mod-loader arguments are still checked for Windows command-injection operators.

Minecraft Setup and First Launch

Choose the edition/framework, version, RAM, port, player limit, world, and credentials supported by the definition. Synix creates the Java launcher and accepts the EULA as part of the managed installation workflow. The first start creates remaining world and config files.
