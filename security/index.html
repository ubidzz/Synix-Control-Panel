Security model

Designed to reduce unnecessary attack surface.

⌂

No public web panel

Synix does not open an internet-facing management port or depend on a hosted relay service.

□

No plugin loader

Game definitions are shipped, validated, and reviewed with Synix instead of executing downloaded extension code.

♙

Normal-user operation

Routine server management runs without administrator rights. Approved Windows-level tasks request elevation only when needed.

●

Protected secrets

Saved passwords and webhook values use Windows Data Protection for the current Windows user, with portable password transfer during encrypted exports.

✓

Command safety

Trusted built-in arguments remain flexible while extra arguments are checked for Windows command-injection operators.

#

Verified packages

Transfer archives use validation and safe extraction rules; releases use manifests, SHA-256 hashes, tests, and readiness checks.

Important limits

What Synix cannot promise.

No desktop tool can make an internet-accessible game server risk-free. Keep Windows updated, use strong unique passwords, expose only required ports, back up worlds, and review official game-server security guidance. Experimental traffic detection is an alerting aid—not DDoS protection from an ISP or hosting provider.

Windows reputation warning

Synix does not currently have a paid code-signing certificate. SmartScreen or Smart App Control may warn about new unsigned releases. Download only from the official GitHub repository and compare the release information before continuing.
