## 13. Live Activity Counter and Privacy

Synix includes an optional live activity counter that estimates the number of running Synix sessions on https://synix.info. This feature is enabled by default. You can turn it off at any time in Settings > Privacy & Security > Share active count without limiting other Synix features. A previously saved off preference is respected.

While enabled, Synix sends an HTTPS presence signal to https://synix.info/api/presence on startup and about every 10 minutes while the app runs, including in the background. The signal contains a random temporary session code and a generic Synix application identifier, with no message body. The session code is kept only in memory and is replaced when a new reporting session starts; it is not a permanent device identifier.

The counter does not upload your name, email address, passwords, server or player information, configuration values, files, or machine identifiers.

For each session, the website's counter stores only a hash of the session code and the time of its latest signal. The public website displays only the aggregate active-session count, which is an estimate rather than a count of unique people. A session stops counting after 15 minutes without a signal. Inactive counter records become eligible for cleanup after 30 minutes and are removed when subsequent counter requests perform cleanup. Synix does not link these counter records to remote-manager accounts or paired-computer identities.

Turning the feature off stops further presence signals and makes one best-effort request to remove the current session. Closing Synix also attempts removal; if removal cannot reach the website, the session stops counting automatically after the inactivity period.

As with any Internet connection, the website's hosting services receive ordinary connection information, such as the originating IP address and request time, and may process or log it under their own privacy policies. This information is not stored in Synix's activity-counter table or displayed in the public count.

## 14. Remote Access Privacy and Security

### 14.1 Optional Access and No Sale of Data

Remote management at https://manager.synix.info is optional and is off until you pair a computer and approve the requesting account in the Synix app on that computer. You can use Synix locally without a manager account. The public activity counter is separate and can be disabled independently.

**Synix does not sell, rent, trade, or disclose your account information, paired-computer information, remote activity, or server information to advertisers or data brokers. Synix does not use this information for targeted advertising or build advertising profiles from it.** Information is processed to provide the features you choose, authenticate access, operate the service, and protect it against abuse.

Remote access is not a zero-storage service. It needs the limited account, pairing, operational, and security records described below. These records are not published in the public activity counter or exposed to other manager accounts through the service.

### 14.2 What Stays on Your Computer

Synix does not automatically upload game worlds, game-server files, configuration-file contents, backup-archive contents, raw console output, or saved game-server passwords. Remote backup and restore run on the paired computer; backup files remain in the locations configured there. If you choose to type a game-console command on the website, its text is processed and relayed to the paired computer, including any sensitive values you put in that text. The manager is not cloud backup storage and does not provide unrestricted remote desktop, Windows command-prompt access, or general file browsing.

Synix keeps its local settings, server list, histories, backups, and pairing state on your computer. A paired computer's private signing key stays in Windows key storage. Synix prefers TPM-backed storage when available and otherwise supports a Windows-protected software key, including on compatible VMs. TPM availability is not a guarantee that a computer is uncompromised.

These statements describe Synix remote management. Games, Steam, mods, Discord integrations, exports, and support reports you choose to share have their own data flows. Do not put passwords or other sensitive information in computer names, server names, or backup filenames, because those labels can appear in the manager.

### 14.3 Information the Manager Processes and Stores

- **Account and authentication:** Your chosen username, account identifier, creation time, security preferences, a salted password hash, encrypted authenticator secret when enabled, passkey public credentials when enabled, and temporary verification/session records. Passwords and verification codes are processed to check sign-in; permanent passwords are not stored as readable text. Synix does not receive your fingerprint, face image, passkey private key, or paired computer's private signing key. Registration does not request a real name or email address.
- **Pairing and connection:** The computer label you choose, a random device identifier, its public signing key, account association, reported key-provider type, pairing approval state, and last connection time. A quiet authenticated relay connection can remain open while Synix runs so the website can wake the paired app immediately. The relay carries wake/disconnect notices and connection metadata, not game files or server snapshots.
- **Displayed status:** Limited server identifiers, names, game names, running state, player counts, uptime, available actions, latest backup time/status, combined CPU and RAM readings from running game-server processes (including their tracked launchers and workers), and separate whole-computer CPU, used/total RAM, and network send/receive rates. Computer network rates include LAN traffic on active gateway adapters; adapter identifiers, IP addresses, packet contents, and browsing destinations are not sent with these readings. The app sends these summaries while an authenticated manager view is active. CPU/RAM updates cover paired computers; detailed server updates cover the selected computer. Updates normally run every 10 seconds and pause after active views close, disconnect, expire, or become hidden as applicable. Other active browser sessions can keep their own views running.
- **Requested actions and backups:** The server/action identifiers, request time, progress/result, and, when you request backup choices, backup identifiers, filenames, dates, sizes, and integrity labels. Backup contents and full local paths are not sent for this feature.
- **Game-console commands:** An opaque game-run identifier, short-lived unlock approval, and command text you submit. Pending text is encrypted in the service database and is removed from that record when delivery is authorized. It is not included in the recent-action list or account-alert records. A delivery result means the text was sent to the game, not that the game accepted or completed it. Game responses and the local process tree are not uploaded.
- **Security and abuse prevention:** Failed sign-in type, grouped attempt count and times, recovery/security event type, and relevant computer labels. Short-lived rate-limit records may use keyed hashes of connection IP addresses and account identifiers. Synix's account-alert records do not contain attempted passwords, verification codes, raw IP addresses, or browser fingerprints. Hosting providers may separately process connection information as explained in Section 14.6.

The website necessarily processes the permitted summaries and commands to provide remote management. HTTPS and encrypted relay connections protect traffic in transit; this is not a claim that the hosting service cannot process the data.

### 14.4 Retention and Deletion

- Account credentials and settings remain until the account is deleted. Approved pairing records remain until the computer is unpaired or the account is deleted.
- Status snapshots and CPU/RAM readings are overwritten by newer readings and become eligible for cleanup after 15 minutes without replacement. Last-connection time remains part of the pairing record.
- Remote command records, results, and returned backup-choice metadata become eligible for cleanup after 24 hours.
- Pending game-console commands expire after 30 seconds. Undelivered text becomes eligible for deletion on expiry or revocation; approved delivery clears it immediately. Console approvals expire within three minutes. The action identifier and fixed delivery result follow the 24-hour action-record period.
- Recovery/security events and failed sign-in alerts become eligible for cleanup after 90 days. Failed sign-ins retain at most the 100 most recent groups; matching failures within a 10-minute period are grouped together.
- Browser sessions expire after 30 minutes without manager requests or after 8 hours overall. Verification attempts expire after 5 minutes; temporary-password recovery expires within 10 minutes and is single-use. Expired verification, recovery, replay-protection, and rate-limit records are removed during cleanup. Incomplete account registrations become eligible for cleanup after 24 hours.

Expiry stops authorization even before a record is physically removed. Routine database cleanup runs during subsequent service requests, at most once every 10 minutes for manager cleanup, so the periods above are expiry or cleanup-eligibility periods rather than promises of erasure at an exact instant. Provider logs and backup copies have separate lifecycles.

Unpairing deletes the selected pairing and its associated remote records from the active service database. Recovery/security history may remain with the account for the period above. Deleting a manager account removes its credentials, pairings, snapshots, commands, and account security/recovery records from the active service database. It does not delete your local game servers, worlds, settings, or backup files. Short-lived abuse-prevention records and provider-held logs or backups are not necessarily erased immediately by either action.

### 14.5 Your Controls and Sign-in Protection

Sign-in requires your password plus an existing passkey or authenticator, such as Google Authenticator. Accounts configured to require both methods keep both requirements. Changing a password, unpairing a computer through the website, and deleting a manager account require fresh verification for that specific change.

Unlocking custom game-console input additionally requires the current account password and fresh verification under the account's existing method requirements. Approval is tied to one browser session, paired computer, saved server and live game run for up to three minutes. A stop, restart, closed console, disabled console setting or lost process prevents further commands. Disconnecting or hiding the manager tab ends that tab's approval. The normal server-action buttons keep their existing sign-in requirements. Only supported game-owned input connections qualify; a unique identifier alone does not authorize writing into a Windows command prompt.

A previously approved paired computer can issue a temporary password if you forget your website password. It cannot select another account. The temporary password does not bypass or remove your existing passkey/authenticator requirements, and you must choose a new password before entering the manager. Completing recovery revokes your other browser sessions.

Synix's manager keeps its browser login token in the current tab's memory, not in cookies, local storage, or session storage. Refreshing or closing the tab loses that login. This does not prevent your browser or password manager from saving credentials if you choose, and it does not describe cookies set separately by hosting/security providers or the public website's translation service.

You can sign out, revoke all browser sessions, or unpair a computer. The local Synix app can disable and unpair its remote connection without signing in to the website. When offline, it stops remote access locally and retries website removal when a connection is available. Restarting the app or Windows does not automatically restore an explicitly removed pairing. Local-only use remains available.
